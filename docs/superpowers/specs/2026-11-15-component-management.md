# 部署后的组件管理

依据已确认的“预设方案起步 + 部署后按需扩展”实施，暂不增加第三方应用、卸载或任意组合框架。

## 方案

完全自由组合会把端口和依赖选择交给用户；只在菜单后调用 apply 会重新初始化系统。采用统一的组件计划与独立执行器，保留五种 Profile 作为经过验证的网络布局。INITIAL_PROFILE 表示起点，PROFILE 表示当前布局，ENABLE_* 保存可选组件。旧配置不需要转换。

## 行为与边界

- components 菜单列出 Docker、Reality/3x-ui、Lucky、Nginx 网关、订阅和 CDN WS 的配置与运行状态；不自动接管外部服务。
- add/repair 先生成计划，检查依赖和端口，只收集缺少的域名及 Docker 源；确认后执行必要模块，不运行 SSH、Swap、系统升级。
- 增装只能扩大能力；网关布局改变必须单独明确确认。保留原订阅模式、节点公网地址、UUID、凭据及配置中的未知字段。
- 每次只允许一个部署或组件操作；完整部署与组件恢复不能互相覆盖候选配置。
- 独立操作目录放在 /var/lib/vps-init，包含 root-only 候选、原配置、步骤状态和备份。失败只支持明确重试，不声称可以撤销软件包、DNS 或签发证书。备份位置与手工恢复限制明确显示。
- 验收成功才提交正式配置；中断后组件 resume 使用同一候选，重新执行幂等步骤，不重新填写配置。
- 第一版不提供卸载和自动回滚，不碰不属于项目的服务；切换和修复可能短暂中断受影响服务。

## 验证

全 Profile 增装计划矩阵、实际 Bash 执行器模拟、失败/中断/锁冲突/取消/状态与配置保留、两种 Docker 源、外部服务保护、CLI 和 PTY 菜单。真实 VPS 的证书签发、SNI 切换和网络连通仍需实机验收。
